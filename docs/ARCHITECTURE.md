# 구조와 승인 경계

문서 ID: ARKEN-ARCH-001 · 버전:1.0 · 기준일:2026-11-17

기본 브랜치 world가 정사이며 PR은 초안이다. records는 명시적 근거, wiki는 본문, indexes는 파생 자료다. details를 본문에 포함시켜 조용한 불일치를 막는다. 자연어의 모든 모순을 검사하는 것은 아니다.

실행기는 신뢰된 기본 브랜치에서 동일 기준의 별도 worktree를 대상으로 실행한다. LLM은 경로·내용 JSON만 반환한다. 최대10개 명시 경로, 파일당30,000자, 조회당4개 ID·8,000자·3회로 제한한다. 근거 예산16,000자와 별도 이름 색인120개를 사용한다. 토큰 수 보장은 아니다.

검토는 독립 문맥이다. warning-only revise는 approve로, blocker 포함 approve는 revise로 정규화하며 원 판정을 보존한다. 자동 중재는 초기 버전에서 생략한다. 같은 모델의 공통 오류는 남는다.

운영자 REVIEW_SIGNING_KEY의 HMAC 서명은 기준 커밋, world 경로/내용 해시, 세 역할 의견을 묶는다. 키·내용·기준이 틀리면 실패한다. 서명은 의견 수집의 무결성이지 내용의 진실성 증명이 아니다. 키가 있는 임의 셸을 생성 에이전트에 주면 경계가 무너진다. 모델은 도구 없는 응답 생성기로 사용한다.

lease는 같은 운영 머신의 worktree만 조정한다. 다중 머신은 중앙 스케줄러가 필요하다. 네트워크 분산 잠금이나 투명한 단계 재개는 아직 구현하지 않았다.

GitHub의 기본 브랜치 직접 push 금지·필수 상태 검사·유지보수자 검토와 Actions secret은 별도 설치가 필요하다. 문서·워크플로만으로 활성화되지 않는다. infrastructure 변경은 world 영수증으로 승인하지 않는다. 최초 부트스트랩만 사용자 지시의 예외이며 독립 합의체 통과로 표시하지 않는다.
